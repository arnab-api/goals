# Multi-hierarchy kv-transfer — is the sub-*sub*-goal carried by the same goal-head motif?

*Coder-32B · 2026-10-02 · notebook `notebooks/diff/05.3_multi-hierarchy.ipynb` · batch eval `scripts/diff/hier_kv_eval.py`*

## Motivation

Two places in the draft lean on a claim we had not tested directly:

1. **Figure 1** says that *different levels of the goal hierarchy are maintained in the same way*. We hypothesised
   this but never validated it empirically.
2. **Section 5 (NRGS)** quietly shifts the level of the hierarchy it studies, while every other experiment in the
   paper fixes the level at the **sub-goal**: the next statement / variable assignment, such as `b = …`.
   A reviewer can fairly ask whether the goal-head story transfers across levels, or whether it is specific to
   statement-level sub-goals.

The cleanest test reuses an intervention we already trust. **kv-(task-)transfer** at the sub-goal level works:
transplant the goal heads' key+value over the task description from a source prompt, and the destination
implements the source's sub-goal (§5.1 / App I.1). Here we run the **same intervention one level down**, where the
"next thing to do" is a *sub-sub-goal*: the second condition of a filter that is already half-written. If the
goal heads selected for the sub-goal level also carry and transfer the sub-sub-goal, under the identical
mechanism, that is direct evidence for the Figure 1 claim.

## Setup

### Notation

Letters are goals; `'` marks a prefilled one. The sub-goal-level kv-transfer is
```
p_src: a'b -> b      p_dst: a'c -> c      kv-transfer target: b
```
One level down, the frontier sub-goal is itself a composition of two sub-sub-goals, and the first one, `x`,
is already written:
```
p_dst      : a'(x'y) -> y
p_src_match: a'(x'z) -> z        kv-transfer target: z
p_src_diff : a'(zx') -> z        (SRC's spec lists z BEFORE x; the code still writes x first)
```
`a` is an ordinary, fully prefilled sub-goal. It keeps the multi-predicate structure of the original setup.

### Operationalization

A sub-goal is a **list filter whose condition is a two-way conjunction or disjunction** of element-wise
sub-sub-goals. The conjuncts come from the existing filter-condition bank (`D.FILTER_TASKS`, about 16 conditions per
datatype). Example (`list[str]`, `and`, `match`), DST side:

```
(1) the number of words
(2) the list of words in `words` that start with the letter a and are palindromes      <- DST: x and y
…
def func(words: list[str]):
    a = len(words)
    b = [w for w in words if w.startswith('a') and                                      <- pivot = the connective
```
In SRC, item (2) reads `… that start with the letter a and contain a digit` (z). In the `diff` order it reads
`… that contain a digit and start with the letter a`, while the code still writes `w.startswith('a')` first.

- **Pivot:** the connective token itself (`" and"` / `" or"`), with no trailing space. All 512 prompts were checked.
  At this point the model has committed to the sub-goal (the filter `b`) and to its first sub-sub-goal (`x`), and is
  about to choose the next sub-sub-goal.
- **Connectives:** `and` and `or`, always the same on both sides. A cross-connective version, forcing `and` where
  the model would write `or`, would create a spec/code inconsistency, so it was left out.
- **Datatypes:** `list[str]` and `list[int]`. These are the filter-bank datatypes; `int` / `str` would need new sub-sub-goal
  banks.
- **Sampling** (`src/diff/hier_data.py`; read-only use of the existing banks, so no current result changes):
  - x, y and z are distinct and pairwise compatible (`D.filter_compatible`, with implications and mutexes closed).
  - `x∘y` and `x∘z` must give different filtered output on an execution pool, so the contrast is observable.
  - `a` is a q-bank sub-goal that shares no concept with x, y or z (explicit overlap map, e.g. `count_long` is
    excluded whenever long / short / length_five is in play).
  - The same seed gives the same (a, x, y, z) for `match` and `diff`, so the two orders are paired.
  - n = 32 per (datatype × connective × order), 256 instances in total.

### Intervention (unchanged from kv-transfer)

`src.diff.functional.run_kv_transfer_intervention`, at the paper's multi-predicate configuration:

- **Transplant:** the source's task-list key+value goes onto the destination's task-list span on the patch heads,
  using GQA-corrected head-wise routing and `pad` alignment.
- **Patch heads:** goal-250 (`head_sets/…/goal_topk/goal__lam20_top250.json`), the same heads used for every
  sub-goal-level result.
- **Boost:** α = 2 OV boost at the pivot. No ablation.
- **Readout:** GoalScope over the same goal-250 heads, taken at the connective pivot.

### Evaluation (unchanged from kv-transfer, plus a rule check)

- **Causal:** `E.judge_causal`. The oracle (claude-sonnet-4-6) decides whether the patched destination's *first*
  computation pursues SRC's sub-sub-goal (z, "src") or DST's (y, "dst"). Descriptions are of the form
  "keep only the words that contain a digit", with the code-so-far given as context.
- **Readout shift:** `E.eval_readouts`, exactly as in kv-transfer. It is valid when the clean SRC readout reads as
  z and the clean DST readout as y; it is shifted when the patched readout reads as z.
- **Rule verdict** (`H.rule_verdict`): a cheap execution check. It completes the prefilled comprehension with
  the first generated line, runs it on a fixed pool and compares the result with `x∘z` / `x∘y`. It is recorded so its
  agreement with the oracle can be measured before anyone relies on it.

Qualitative pilot (notebook, 5 hand-written conjunction tasks × both directions, `span=list`): **10/10** patched →
SRC's sub-sub-goal. Patched readouts at `and` verbalize the transplanted condition, e.g.
"I'm checking if the current string is a palindrome…" and "I'm checking for negative numbers."

### Findings

1. **The sub-goal-level goal heads transfer the sub-sub-goal, at ceiling.** With exactly the heads and the mechanism
   used at the sub-goal level, 255/256 patched destinations write SRC's next sub-sub-goal z instead of their own y.
   That matches the sub-goal level itself: 0.97–1.00 causal for the same heads and config.
   This holds for both connectives and both datatypes. The one miss (list[int], or, diff) was judged "neither", not "dst".
2. **The goal heads' readout follows the transplant.** Where the readout test is valid, 94% of patched readouts at
   the connective pivot verbalize z. So the same heads that report the sub-goal at `=` report the sub-sub-goal at `and`.
3. **What is transferred is content, not spec position.** In `diff` the transplanted spec lists z first and x
   second, while the destination's code has already written x. A positional "the 2nd listed condition" signal would
   then point at x, the already-done condition. Instead `diff` performs exactly like `match` (1.00 / 0.97 causal).
   The model takes the *not-yet-done* sub-sub-goal from the transplanted description, consistent with the
   content-identity reading of the sub-goal-level results (App I.3: the query carries *what to look for*).

## Caveats

- **Sufficiency, not specificity.** These results show the goal-250 heads are *sufficient* to carry the sub-sub-goal.
  They do not show that *only* these heads carry it, nor that a sub-sub-goal-level localization would recover the
  same heads. A control-head baseline was deliberately deferred; it is the first thing to add before this goes into
  the paper. Reference at the sub-goal level (multi-predicate kv-transfer, py→py, α=2, `pad`, n=32 per datatype):
  goal-250 causal 0.97–1.00, control-250 **0.00** on all four datatypes
  (`results/diff/<M>/kv_transfer/multi_pred/ph-control250_250__…`).
- **α = 2 and `span = list`.** These are the paper's kv-transfer settings. The OV boost and the full task-list span
  are generous, and ceiling effects can hide differences, e.g. between `match` and `diff`. α = 1 and the
  clause-only span (`SPAN="clause"` in the notebook) are the natural stress tests.
- **Readout validity is ~74%.** 66 of 256 readouts are invalid, nearly always because one clean readout does not
  name its own condition. The patched-readout shift is only computed over the valid ones. At the connective pivot the
  clean readout often verbalizes the whole conjunction ("checking if the number is even and greater than zero") or
  drifts to the other side's condition, and the judge counts that as neither. The `and`/`or` pivot is a less
  clean readout position than the sub-goal-level `=`.
- **The rule check is stricter than the oracle, and every disagreement is a correct-but-different z.** All 15
  non-"src" rule verdicts were inspected:
  - Equivalent forms that differ on the pool's negative numbers:
    `int(abs(x)**0.5)**2 == abs(x)` for perfect_square; `50 < abs(x) < 100` for abs_over_fifty.
  - Calls to an undefined helper, `is_prime(x)` → `NameError`.
  - `int(x**0.5)` on negatives → `TypeError`.
  - A case-insensitive `'e' in w.lower()`.
  - A comprehension cut at the line break.

  None of them is y. On these data the oracle verdict is the one to report; the rule check is a reliable *lower bound*
  (≥ 0.84 everywhere).
- **list[int] clean runs are imperfect.** The unpatched source and destination write their own condition 81–97% of
  the time; the misses are the same equivalent-form issue. This does not affect the causal result, which is about
  the patched output.
- **Scope:** py→py only, Coder-32B only, and two-way compositions only.

## Next steps

1. **Control-head baseline** (control-250 later-half, same config) and **α = 1**: the minimum to make this a paper result.
2. **Span ablation** (`list` → `frontier` → `clause`): does the distinguishing clause alone suffice?
3. **Localize at the connective pivot** with the head-mask pipeline and measure overlap with the sub-goal-level goal
   heads (Jaccard against a layer-matched chance level). This is the direct "same motif" evidence; sufficiency alone
   does not establish it.
4. **Wider coverage:**
   - `int` / `str` sub-sub-goal banks, built in a separate dataloader so the existing banks are not touched.
     Example: "greater than 10 and divisible by 5" vs "greater than 10 and smaller than 100".
   - Depth 3 (`x and y and w` vs `x and y and v`).
   - Cross-language once the filter conditions have clean `&&`/`||` forms.
5. Optionally, recompute the rule verdict on the first top-level condition only (cut at the first `and`/`or`/`]`).
   The raw generations are saved, so this needs no re-run.
