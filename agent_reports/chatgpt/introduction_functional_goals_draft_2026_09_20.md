## Introduction

Do LLMs have goals? We often explain an AI's behavior by describing what it is trying to achieve. Such explanations adopt an *intentional stance*: they predict a system's actions in terms of its goals and beliefs (Dennett, 1987). What properties of the system make these predictions work? We take a functional approach to this question, asking how a goal organizes action, independently of the physical structure that realizes it. In Bratman's planning theory, intentions guide subsequent reasoning and conduct: an agent can settle on an end while leaving details of its implementation open (Bratman, 1987; Bratman et al., 1988). We investigate a corresponding computational role in LLMs: **does an LLM contain an internal representation of a goal that guides its subsequent actions?**

Drawing on accounts of intention and goal-directedness, we examine three attributes of such a representation. **Pre-commitment:** the system represents an upcoming operation before initiating it, and this representation guides its execution (Bratman et al., 1988; Williams, 2026). **Plasticity:** the same goal admits different means of realization as the environment changes (Lee and McShea, 2020; Williams, 2026). **Persistence:** the goal continues to organize behavior over time. Persistence has two related aspects: sustaining a goal during its execution, and recovering its pursuit after an obstacle or disruption (Bratman et al., 1988; Lee and McShea, 2020). These attributes provide concrete questions about what a goal encoding does: when it becomes available, which implementations it can guide, and how it relates to the unfolding computation.

Consider a programmer implementing merge sort, a task that decomposes into several sub-tasks: *split the array*, *sort each half*, and *merge the sorted halves*. The sub-goal “merge the two halves” specifies an operation that may be implemented using different loops, variable names, or programming languages. It can guide many successive steps of code generation before giving way to the next sub-goal. In the terminology of Williams (2026), a representation of this operation can be both *proximal*, concerning an action about to begin, and *abstract*, admitting different concrete realizations. We study this level of goal representation: the intermediate operation an LLM is about to carry out in pursuit of a broader task.

We investigate these questions in a coding setting with multi-step specifications. Each task requires several operations, allowing us to distinguish the next sub-goal from the broader specification and the steps already completed. We examine the model's internal states at token positions before the next implementation begins, then intervene to test what those states control. Our main experiments use Qwen2.5-Coder-32B-Instruct. Building on work identifying portable representations of functions and filtering predicates (Todd et al., 2024; Sen Sharma et al., 2026), we ask how a model represents and acts on an upcoming operation within an extended computation.

We find that a sparse set of attention heads, which we call *goal heads*, carries a decodable representation of the next sub-goal before implementation. We introduce *GoalScope*, a probe that caches these heads' contributions at a single token position and injects them into a separate model run to generate a natural-language description. The probe receives information about the source task only through the injected activations. Its descriptions reveal what the model is about to do before the corresponding code has been written. The same captured encoding can also guide a different realization of the operation: transplanting it from a Python context into a C++ context can trigger the source operation in C++, and vice versa. This provides a concrete test of plasticity, in which goal identity is preserved while the generated implementation adapts to a different programming language.

The goal heads also mediate execution in the model's original context. Preserving their access to task information largely preserves the ability to implement the upcoming operation when other upper-layer heads lose access to that information. Conversely, blinding a broader set of goal heads sharply impairs implementation. Together with transfer, these interventions establish a causal role for the identified heads in guiding the next action. We further examine how that action is selected: interventions on the heads' keys and values change the task information they read, while query interventions test how completed work influences the next sub-goal. These experiments let us connect the content of the goal encoding with the computation that selects and implements it.

We also trace the encoding through the tokens that implement a sub-goal. Comparing head contributions across positions and contexts reveals goal-specific representational structure through much of the implementation. This temporal analysis complements verbalization and transfer by asking how the representation develops as the model acts on it. Persistence also raises a question about completion: when should pursuit of the current sub-goal end? Accounts of intention include conditions for releasing a goal after it has been achieved (Cohen and Levesque, 1987). We examine this transition through boundary-signal interventions that can induce the model to advance or remain with the current sub-goal. We discuss persistence in the face of obstacles separately through qualitative examples in the appendix, including cases in which the model fails to recover pursuit.

We replicate the readout and transfer findings across model families and sizes, and explore whether heads localized on coding tasks also expose operations inferred from natural-language demonstrations. Our experiments connect an abstract sub-goal with identifiable neural representations: we can read it before implementation, use it to guide different realizations, and trace its relationship to the model's subsequent computation.

## Drafting notes — not manuscript text

- **Framing and tone.** The opening moves from goal attribution to a functional question, then to attributes, a concrete example, and interventions. It avoids making anthropomorphism or subjective experience the organizing problem. The three attributes are explicitly a synthesis drawn from several accounts. Pre-commitment uses our operational definition; it does not silently include all of Williams's stronger senses of commitment.
- **Temporal persistence.** The draft gives this a paragraph alongside completion and transition, rather than presenting it as a third readout score. The sentence about goal-specific structure is supported by preliminary saved outputs, but the final analysis still needs to be prepared for the paper. It does not claim that readouts stay correct at every token, that an unchanged state is retained, or that causal influence has been established throughout the implementation. I avoided “long token sequences” until implementation lengths are characterized.
- **Obstacle persistence.** This remains one sentence about a qualitative appendix discussion, including failures. It is part of the functional question, not an announced empirical success. That sentence anticipates the examples you plan to add; I have not treated a systematic recovery evaluation as either completed or required for this draft.
- **Completion.** The boundary experiments motivate release and transition, but the draft describes their demonstrated intervention effect—advancing or staying—without identifying a verified semantic completion detector.
- **Causal evidence.** The readout/transfer head set and the broader set used for the strongest impairment result remain distinguished. The draft does not call a sparse set the model's sole bottleneck. It also does not equate implementation transfer with verified functional correctness of the whole generated program.
- **Mechanistic theory.** The query/key-value paragraph introduces the selection question without making the DIFF theory a premise of the introduction or claiming that progress is its only determinant. The current paper's asymmetric evidence fits this wording.
- **Generalization.** Cross-family readout and transfer are presented as replications. Natural-language generalization remains exploratory, matching the current text and qualitative examples rather than announcing broad quantitative success.
- **Abstract alignment to revisit.** The current abstract defines the target as persisting “in the face of obstacles” and then says “We verify” several properties. With a qualitative obstacle appendix, that wording could imply more than the planned evidence establishes. When revising the abstract, distinguish temporal representational evidence from qualitative obstacle behavior. I have not changed the abstract here.
