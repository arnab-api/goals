# Introduction draft: goal pursuit through repeated computation

September 22, 2026. Based on the current introduction, Figure 1, goal-head readout and intervention sections, OVReader appendix, DIFF section, and persistence results. This is a separate draft for discussion; no Overleaf files or earlier reports have been changed. Author–year citations are mapped to bibliography keys below.

## Proposed introduction

Do LLMs have goals? We often explain a system's behavior in terms of what it is trying to achieve. Such explanations adopt an *intentional stance*, predicting actions in terms of goals and beliefs (Dennett, 1987). We investigate the internal computations that could support this description: **does an LLM represent a goal that guides its actions, and how does it continue pursuing that goal as it generates tokens?**

We take a functional view of a goal representation, asking what role it plays in organizing action. In Bratman's planning theory, intentions guide subsequent reasoning and conduct while leaving details of their realization open (Bratman, 1987). A programmer can intend to find the length of the longest word before deciding how to implement the operation. The same end can be realized with a Python expression or a C++ loop, and can organize many individual steps before it is achieved. Drawing on accounts of intention and goal-directedness, we investigate three corresponding properties: an encoding that **precedes and causally guides action**; **plasticity**, allowing the same goal to be realized in different environments; and **persistence**, sustaining pursuit over the course of execution (Williams, 2026; Lee and McShea, 2020).

How might a transformer implement these properties? At each token position, the model computes new activations from the available context and uses them to generate the next token. The generated token then becomes part of the context for subsequent computation. A goal can therefore continue to guide behavior through successive encodings of the same operation. Figure 1 illustrates this possibility: the abstract state “doing this sub-goal” can correspond to a sequence of neural states, each computed in the context of the task and the work completed so far. We investigate **functional persistence through recomputation**: whether the content of a goal recurs in the model's changing representations as its implementation unfolds. This view connects two questions that are usually studied separately: how an upcoming operation is represented before action, and how the model continues selecting steps toward it during generation.

We study these questions in a controlled setting with multi-step coding tasks. Each prompt specifies several operations, and a prefilled implementation completes some of them. This lets us distinguish the broader task, the work already done, and the next *sub-goal*. We focus on this immediate operation, such as “find the length of the longest word,” rather than the entire program or an individual output token. In Williams's (2026) terminology, such a representation can be both *proximal*, concerning an action about to begin, and *abstract*, admitting different concrete realizations. Our main experiments examine Qwen2.5-Coder-32B-Instruct, with readout and transfer replications across model families and sizes.

We first localize the sub-goal encoding to the outputs of a sparse set of attention heads, which we call *goal heads*. Motivated by prior work on portable representations of functions and filtering predicates (Todd et al., 2024; Sen Sharma et al., 2026), we identify heads whose outputs can transfer an operation between contexts. Building on Patchscopes (Ghandeharioun et al., 2024), we introduce *GoalScope*, which captures these heads' contributions at a source token position and injects them into a separate model run. The probe receives information about the source task only through these activations. With a verbalization prompt, it describes the operation the source model is about to implement. With a code prompt in another programming language, it can induce that operation in a different sequence of tokens. We obtain both readouts and implementation transfers from positions preceding the operation's first implementation token. These experiments connect an early, readable representation with the ability to guide different realizations of the same sub-goal.

We then test the role of the goal heads in the model's own execution. Preserving their access to task information largely preserves implementation performance when other upper-layer heads lose access to that information. Conversely, restricting a broader set of goal heads sharply impairs the model's ability to implement the next operation. These interventions establish a causal role for the identified heads during ordinary generation. Using their value and output projections, we also introduce *OVReader* to trace where the sub-goal becomes readable in intermediate residual states. Together, these analyses let us examine both the construction of a goal representation within a forward pass and the heads through which it influences action.

To study temporal persistence, we follow the goal-head outputs through the tokens implementing a sub-goal. Although the activations change across positions, encodings of the same sub-goal remain more similar than encodings of different sub-goals, including comparisons across contexts and programming languages. This result provides evidence of continuing goal-specific structure during execution. It is consistent with the model repeatedly constructing an encoding of the operation it is pursuing. Persistence in the face of obstacles is a stronger requirement: an agent must recover pursuit when its current course is disrupted. Our models show limited robustness to misleading implementation prefixes, which we examine separately in the appendix. Temporal continuity of goal content and recovery from an obstacle are therefore distinct aspects of goal pursuit in our setting.

Finally, we ask how the model determines which sub-goal to encode as the context changes. We propose that it selects unfinished work by comparing the task specification with its current progress. This provides a possible account of both continuing the present sub-goal and moving to the next: the model can recover what remains to be done from the evolving context. We test this account by intervening on the goal heads' attention queries and key–value states. Replacing task-related key–value states redirects the operation the model implements; query transfers test how information about completed work changes this selection. The effects support a role for both task and progress information, while their sensitivity to task order constrains a simple account based on their difference. Our experiments thus connect abstract sub-goal content with a causal mechanism for action and a testable account of how that content is reconstructed as generation proceeds.

## Editorial notes — not manuscript text

**The central change.** The draft introduces recomputation before the experimental setup, so it organizes the paper rather than appearing as a qualification to pre-commitment. The functional object is the sub-goal being pursued; its neural realizations can change with position. “Precedes and causally guides action” replaces “pre-commitment” as the first empirical criterion. This still fits *Intent Before Action: Goal Encoding in LLMs*, without treating early decodability as a decision that has been irreversibly settled.

**What is established versus hypothesized.** New activations are computed at each position by the architecture. Establishing that their goal content is reconstructed specifically by comparing task with progress is a further mechanistic claim. GoalScope reveals recurring readable content; OVReader traces accessibility across layers; affinity reveals continuing goal-specific structure. None alone separates reconstruction from reuse of previously encoded information. The introduction presents reconstruction as the organizing account being investigated and DIFF as a possible implementation, rather than declaring the entire mechanism proved. In particular, OVReader's first successful readout need not be the first layer at which the model represents the goal.

**A qualification to the layer-depth argument.** I would not put “traditional pre-commitment is infeasible in LLMs” in the paper. Functional commitment does not require an unchanged vector. Architecturally, a chain that repeatedly passes updated latent information across positions through attention must also advance through layers; it cannot implement arbitrarily many such updates at fixed depth. But an earlier position's cached keys and values can be accessed directly by many later positions. Token distance alone does not consume an additional layer per token. Thus the depth argument constrains a particular recurrent implementation, rather than ruling out persistent influence or commitment. This follows from the attention and decoder dependencies in [Vaswani et al. (2017), §§3.1–3.2](https://arxiv.org/html/1706.03762v7). The draft accordingly describes fresh computation from available context without asserting that all continuity passes exclusively through emitted tokens.

**Persistence text currently conflicts with the new framing.** [The main persistence section](../../Overleaf-draft/Goals-Overleaf/Text/persistance.tex) explicitly says the encoding is maintained “rather than re-derived token by token” and “rather than recomputed line by line.” Those statements should change when you revise the manuscript. Similarity across positions does not distinguish these mechanisms. The appendix also repeatedly equates persistence with retention of the pivot encoding. The draft instead describes the measured result—continuing goal-specific representational structure—and then its compatibility with recomputation. It does not claim that all implementation positions have faithful verbalizations or demonstrated causal effects.

**Transfer and temporal persistence answer different questions.** GoalScope uses a captured source vector repeatedly during the destination generation. This establishes its ability to guide another realization; it does not show that one early intervention in the source autonomously controls the entire later implementation. The draft keeps transfer in the abstraction/plasticity paragraph and native temporal evidence in a separate paragraph.

**Figure 1 and scope.** The draft follows the figure's longest-word example, context-dependent recomputation, and cross-language transfer. Its first label could become “Before action” or “Goal formation” in place of “Pre-commitment.” The figure's claim that the model re-encodes the goal at *every* token should be distinguished from the experimental evidence about affinity across implementation positions. The task/progress comparison is the proposed mechanism illustrated by the schematic. I did not announce the boundary-signal experiments because the current appendix says to remove them from this version. I also omitted a broad non-code generalization claim while that main-text section is under revision. The obstacle paragraph reflects the current appendix's evaluation, rather than the earlier plan for only qualitative examples.

## Citation mapping

The three attributes are our experimental synthesis, not a definition quoted from any single philosopher. In particular, Lee and McShea's persistence concerns robustness to perturbation; it should not be cited as if it specifically defined cosine similarity across neural states as temporal persistence.
